# 三义漫剧评审规则 V2.3（执行层）

> 本文件是评审线**唯一常驻规则文件**；`references/` 下的参考层按需读取。
> **路径约定**：本文件提到的 `references/`、`scripts/` 指本 SKILL.md 所在目录（Kimi Code 中即 `${KIMI_SKILL_DIR}`）；`reviews/` 等指用户项目目录。
> **只评分，不写作**：本 skill 只输出判断、分数、评级、证据和改法方向，不产出任何剧本内容。

---

## 0. 会话前提：写评隔离

- 评审在**新会话**中进行。若本会话刚写过或改过这份稿子，先建议用户开新会话；用户坚持继续时，在评审信息里注明"同会话评审，结论可能偏高"。
- **可读**：用户指定的评审材料——剧本正文、分集大纲、人物小传、世界观设定、企划案。
- **不读**：写作过程文件——写作思路、设计说明、修改记录、自检记录、开发卡、剧情状态表、下集简报之类。拿不准某个文件算不算过程文件时，先问用户。
- **不加载任何写作类 skill**。项目的 `AGENTS.md` / `CLAUDE.md` 里若有写作流程要求，评审会话一律不适用。
- **兼容三义写作线目录**：项目里如有 `01-设定/`、`02-状态/`、`03-大纲/`、`04-剧本/` 这套结构，只读 `01-设定/`、`03-大纲/` 和 `04-剧本/` 正文，整个 `02-状态/` 不读。
- 剧本正文里如混有写作标注（如"结尾追更点：……""E2 强度 3"），一律忽略、不作证据，并在评审信息中注明"正文含写作标注，已忽略"。

## 1. 定位与评分原则

- 评什么：剧本内容能否让观众**看完第一集就想继续看、一集接一集停不下来**。
- 不评什么：投流、切条、封面、分发、投放素材；与内容无关的商务材料。
- **不做什么**：写稿、续写、改稿、扩写大纲、写替换场景或整段替换台词。用户在评审会话里要求这些时，说明本 skill 只做评分，建议另开写作会话处理；评审结论可以作为写作会话的输入。
- 五条原则：
  1. 不为鼓励而抬分；
  2. 不因设定复杂、名词多或文笔漂亮而高评；
  3. **先完成六视角判断，再打分**；不先定总分再找理由；
  4. 每个关键判断必须能回指原文、集数、场次或具体缺失项；
  5. 剧情必须好懂、有趣、情绪直接，不把理解难度当高级。

## 2. 评审模式（按材料选择，必须在报告中声明）

| 材料 | 模式 | 评级写法 |
|---|---|---|
| 一句话梗概、企划案 | 立项潜力评审 | "潜力 A"等；注明"正文未验证" |
| 人物小传、世界观、分集大纲 | 开发准备度评审 | "准备度 B"等 |
| 前 3 集 / 前 10 集 / 完整正文 | 落地执行评审 | 直接写评级，完整跑前 10 集审计 |
| "快速看看值不值得继续" | 轻量评审（§7） | 不出总分、不出评级 |

潜力分、准备度分不得写成落地执行评级。

## 3. 证据纪律

- 区分四类：**原文事实 / 合理推断 / 未验证 / 外部事实**。不把推断写成事实，不因材料缺失脑补得分。
- 长文先建立集数、场次索引再评。DOCX/PDF 先提取全文；只有版式或扫描页影响判断时才看页面；做不到时声明"未完成的文件层验证"。
- 涉及当前市场新颖性、竞品、政策、法律、医疗、金融等事实时联网核验；没核验只能写"文本新颖性判断"。

## 4. 评审流程（固定顺序）

1. 声明评审信息：文件名/版本、材料类型、覆盖集数、评审模式；
2. 建立集数场次索引，区分四类证据；
3. **六视角判断**（`references/六视角复核.md`），并按 `references/剧本质量检查项.md` 在原文中取证；
4. 材料覆盖前 10 集时，先做"期待与信息差总览"，再逐集审计开场、升级、起伏、**集尾**（`references/前10集审计.md`）；材料不足标"未验证"，不判 0 分、不宣称通过；
5. 按 `references/评分模型与锚点.md` 给 9 个细项打分（有校准样例先比对，没有就按锚点正常给分并标"未校准"——**不强制取下限**）；
6. 执行 §5 硬门槛：总分对应的评级与门槛冲突时，取门槛上限，写"原始分 + 门槛调整后评级"；
7. 总分在切线附近时做边界复核（见评分模型第二节）；
8. 按 `references/输出模板.md` 输出；
9. 给出开发决策（§6）与 P0/P1/P2 建议（§8）；
10. 双格式交付（§9）+ 交付前 QA（§10）。

## 5. 硬门槛

规则：**门槛只限制评级上限，不改细项分数；多条同时适用时取最严的一条，不叠加。** 全部为"不得"，没有"通常"，没有自由裁量。

**A. 分数型门槛**

| 条件 | 评级上限 |
|---|---|
| 创新度 < 4/7 | 不得高于 B |
| 创新度 < 6/7 | 不得评 S |
| 情绪价值 < 18/35 | 不得高于 B |
| 故事情节 < 13/25 | 不得高于 B |
| 主角塑造 < 5/10 | 不得高于 B |

**B. 前 10 集门槛**（落地执行评审，材料覆盖前 10 集时适用；判定细则见 `references/前10集审计.md`）

| 条件 | 评级上限 |
|---|---|
| 第 1 集开场不成立 | 不得高于 B |
| 集尾失败 1 集 | 不得评 S |
| 集尾失败 2 集 | 不得高于 B |
| 集尾失败 ≥ 3 集 | 不得高于 C |
| 完整通过 8–9 集 | 不得评 S |
| 完整通过 6–7 集 | 不得高于 B |
| 完整通过 ≤ 5 集 | 不得高于 C |
| 材料未覆盖前 10 集，或大纲不足以判断 | 前 10 集门槛标"未验证"；不得评 S |

**集尾权重最高的体现**：同样两集出问题，出在集尾的直接"不得高于 B"；出在开场、升级或起伏的只是"不得评 S"。

**C. 材料门槛**：立项潜力、开发准备度评审的评级必须带"潜力 / 准备度"字样，不得写成落地执行评级。

## 6. 开发决策（必须给，不得只给分）

先答三问：**能不能卖**（一句话卖点清楚、有差异）｜**能不能追**（前 10 集持续制造问题、关系和代价，集尾接得住）｜**能不能做**（AI 漫剧能稳定制作、资产可复用、成本可控）。

再四选一：建议直接推进 / 建议修改后推进 / 建议重做核心机制后再评 / 当前不建议推进。

评级为 D，或前 10 集集尾失败 ≥ 3 集时，不得选"建议直接推进"。

## 7. 轻量评审（快速看稿）

固定五项：
1. 评审信息（材料、覆盖集数、模式：轻量）；
2. 一句话锐评；
3. 门槛检查：**只查不依赖分数的门槛**——§5 B 组（第 1 集开场、集尾失败数、完整通过数、覆盖范围）逐条标 通过 / 不通过 / 未验证；§5 A 组分数型门槛统一写"轻量模式不评"，可另用一句话提示明显风险（如"创新度可能不足"），但不写数字；
4. 至多 3 项致命问题（位置 + 证据 + 改法方向），集尾问题排最前；
5. 开发决策（四选一）。

**不出总分、不出评级**，不写"A 档水平""80 分左右"等变相评级。需要正式结论时转完整评审。轻量模式可直接在对话中回复，不强制双格式。

## 8. 优化建议标准

- 分级：P0（立项级，不改不建议推进）/ P1（追看与情绪）/ P2（表达与制作）。同一级内，**集尾问题排最前**。
- 每条 P0/P1 写清：`位置 → 文本证据 → 问题本质 → 对追看的影响 → 改法方向 → 预期作用 → 连锁影响`。
- **改法方向**要具体到能执行：改哪一集哪一场、把什么换成什么类型的事件或动作、放到什么位置。例如"EP02 第一场改为直接展示 EP01 结尾契约被当众解除的结果，场景介绍压到反应镜头里"。
- 可以附**一句**示意（一句台词或一个动作描述）帮助理解，**不写整场、整段或整集的替换稿**。
- 单集开场或集尾不通过时，必须指出失效环节，并给出上面这种粒度的改法方向。
- 禁止只写"加强人物魅力""增强冲突""提升节奏""增加反转""强化情绪"。
- 不展开写作教学，不引用任何写作 skill 的规则编号；问题用本 skill 的检查项名称描述（如"删名测试未通过""报告链"）。

## 9. 双格式交付（正式评审）

1. 正式评审先写 Markdown 母版，放在项目的 `reviews/` 目录（没有就新建），文件名如 `EP01-10_评审_2026-09-29.md`；
2. 运行 `python3 scripts/render_review_html.py <评审.md>`（脚本在本 skill 目录下），在同目录生成同名 `.html` 离线预览；
3. HTML 不单独编辑；MD 改了必须重新生成；生成失败保留 MD 并如实报告，不得声称双格式已完成；
4. 最终答复先给 HTML 路径，再给 MD 路径。

## 10. 交付前 QA

- [ ] 在新会话评审，或已注明"同会话评审"；未读写作过程文件；未加载写作类 skill
- [ ] 已完整读取材料，未以截图代替全文；已声明评审模式与未验证项
- [ ] 六视角已判断或标"不触发"，且判断先于打分；扣分项有《剧本质量检查项》对应的原文证据
- [ ] 9 个细项已标"已校准 / 未校准"，未校准项已给置信度；未强制取下限
- [ ] 分项之和等于总分；总分在切线附近时已做边界复核
- [ ] 已逐条执行硬门槛，取最严一条，未叠加；冲突时已写原始分与调整后评级
- [ ] 前 10 集材料存在时已逐集审计，未合并成一句总体评价；集尾失败数与完整通过数已分别写明
- [ ] 优点与问题均有文本证据；建议具体到集数、场次、台词；集尾问题排在同级最前
- [ ] 已给出三问与四选一开发决策
- [ ] 正式评审已生成同目录同名的 MD 与 HTML；轻量模式未出总分与评级
- [ ] 未写任何替换稿、续写或改稿；建议停留在"改法方向 + 至多一句示意"
- [ ] 单模型执行多视角写"多专家视角融合"，未冒称"多模型会审"

任一项未完成，不得声称"严格执行三义评审规则"。
